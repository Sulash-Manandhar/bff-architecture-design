## 3. The six data patterns (the core of the demo)

All five read routes call one shared `fetchFeed()` in `lib/feed.ts`. Only the **call site** differs.

1. **Server Component** — `app/server/page.tsx`
   `async` page, `await fetchFeed()`. Browser gets finished HTML. No client JS, no spinner.
   Also shows `export const instant = false` (opting out of instant rendering).

2. **Client Component + Server Action** — `app/client/page.tsx` → `app/(demo)/feed-panel.tsx`
   `useQuery({ queryFn: () => getFeed() })` calling a `"use server"` function.
   Teaching point: server actions are **queued**, so reads through them serialize.

3. **Route Handler** — `app/api-route/page.tsx` → `feed-fetch-panel.tsx` → `app/api/feed/route.ts`
   Plain `fetch("/api/feed")`. The only demo visible in DevTools → Network.
   Uses `connection()` to defer to request time so it isn't prerendered at build.

4. **Hybrid / streaming** — `app/hybrid/page.tsx` → `feed-stream.tsx`
   Server creates the promise **without awaiting**, passes it down; client reads it with
   React's `use()` inside `<Suspense fallback={...}>`. Fetch starts before the first byte;
   shell paints instantly. Builds as a partial prerender (`◐`).

5. **Caching** — `app/caching/page.tsx` → `lib/feed.ts#fetchCachedFeed`
   `"use cache"` + `cacheLife("minutes")` + `cacheTag("feed")`.
   `generatedAt` is stored *inside* the entry, so a frozen timestamp proves a cache hit.

6. **Mutation** — `app/mutation/page.tsx` → `note-form.tsx` → `app/actions/notes.ts`
   Form posts to a `"use server"` action: validate → write → `updateTag("notes")`.

## 4. React Server Components model

- **Server Components by default** — pages, `feed-grid`, `feed-card`, `demo-header`, `flow-diagram`.
- **`"use client"` boundary** — `providers`, `feed-panel`, `feed-fetch-panel`, `feed-stream`,
  `feed-error`, `note-form`, `revalidate-button`. Explain: the directive marks the *boundary*,
  everything below it is client.
- **Server → Client props must be serializable** — but a **promise** can cross (`feed-stream.tsx`).
- **`"use server"`** — `app/actions/feed.ts`, `app/actions/notes.ts`. A `"use server"` file may
  only export async functions — that's why `INITIAL_NOTE_FORM_STATE` lives in `lib/note-input.ts`.

## 5. React 19 APIs

| API | Where | Purpose |
|---|---|---|
| `use(promise)` | `feed-stream.tsx` | Suspends a client component on a server-started promise |
| `<Suspense>` | `app/hybrid/page.tsx` | Streaming boundary + skeleton fallback |
| `useActionState` | `note-form.tsx` | `[state, action, isPending]` — progressive-enhancement form |
| `useTransition` | `revalidate-button.tsx` | Non-blocking pending state around a server action |
| `<form action={fn}>` | `note-form.tsx` | Form posts to a function; works before hydration |

## 6. Caching & invalidation (Next.js Cache Components)

- `cacheComponents: true` — the opt-in flag.
- `"use cache"` — function-level directive (`fetchCachedFeed`, `listNotes`, `sitemap`'s `lastModified`).
- `cacheLife("minutes" | "hours")` — named lifetime profiles.
- `cacheTag(TAG)` — gives the entry an invalidation handle.
- `updateTag(TAG)` vs `revalidateTag(TAG)` — **the key distinction**: `updateTag` expires the
  entry *now* so the author reads their own write; `revalidateTag` refreshes in the background.
- `fetch(..., { cache: "no-store" })` — the uncached path in `fetchFeed()`.
- `connection()` — opt a route handler out of build-time prerendering.
- Build-output legend: `○` static · `◐` partial prerender · `ƒ` dynamic.

## 7. Data fetching & the BFF idea

- **Backend for Frontend** — the app owns a thin server layer that talks to the upstream;
  the browser never sees upstream URLs or credentials.
- **Upstream** — JSONPlaceholder (`/posts`, `/users`, `/comments`).
- **Parallel fetching** — `Promise.all` in `loadFeed()`.
- **Join/shape on the server** — `Map` lookup for author names, `reduce` to count comments
  per post. The client receives a flat `FeedItem[]`, not three raw payloads.
- **Typed upstream vs typed output** — `RawPost`/`RawUser`/`RawComment` → `FeedItem`.
- **Error propagation** — `get()` throws on `!response.ok`; the route handler catches and
  returns `502` with a generic message (no internals leaked).

## 8. TanStack Query (v5)

- `QueryClient` + `QueryClientProvider` — `app/providers.tsx`.
- **Singleton-per-browser pattern** — `browserQueryClient ??= createQueryClient()`; a fresh
  client on the server so requests don't share cache.
- `defaultOptions`: `retry: 1`, `refetchOnWindowFocus: false`.
- `useQuery` — `queryKey`, `queryFn`, and v5 state flags `isPending` / `error` / `data`.
- `refetch()` — wired to the "Try again" button.
- **Query keys as cache identity** — `["feed"]` vs `["feed", "api-route"]` keep the two demos apart.

## 9. Forms, validation & the trust boundary

- `lib/note-input.ts` — pure validation, no server-only imports, so the client can share
  `NOTE_MAX_LENGTH` without pulling the note store into the bundle.
- **Discriminated union result** — `{ ok: true, text } | { ok: false, error }`.
- **Validate server-side regardless of client attributes** — `required` / `maxLength` in the
  HTML are UX; `validateNoteText` in the action is the actual trust boundary.
- **Error state returned, not thrown** — the action returns `{ status: "error", message }`.
- **Simulated latency** — `WRITE_LATENCY_MS` so the pending state is visible.
- **In-memory store caveat** — `lib/notes.ts` resets on restart, isn't shared across instances.

## 10. SEO & social

- **Single source of truth** — `lib/site.ts`: `SITE` + the `ROUTES` table + `routeMetaFor()`.
- **Origin resolution** — `NEXT_PUBLIC_SITE_URL` → `VERCEL_PROJECT_PRODUCTION_URL` → localhost.
- **Root `metadata`** — `metadataBase`, title `template`, keywords, authors, `alternates.canonical`,
  `openGraph`, `twitter` (`summary_large_image`), `robots` + `googleBot` directives.
- **`viewport` export** — `themeColor` per color scheme.
- **Per-route metadata** — `routeMetadata(path)` in `lib/metadata.ts`; pages inherit the rest.
- **`opengraph-image.tsx`** — one per route, exporting `alt` / `size` / `contentType` / default `Image()`.
- **`next/og` `ImageResponse`** — `lib/og-image.tsx`, 1200×630. Note: Satori resolves **no**
  Tailwind and no CSS variables, so colors are inlined and every element needs explicit `display`.
- **`robots.ts`** — allow `/`, disallow `/api/`, point at the sitemap.
- **`sitemap.ts`** — generated from `ROUTES`; `lastModified` is `"use cache"`d so reading the
  clock doesn't make the route dynamic.

## 11. Styling & UI

- Tailwind v4 `@theme inline` mapping CSS vars → utility color tokens (`bg-surface`, `text-muted`,
  `border-border`, `text-accent`).
- Light/dark via `@media (prefers-color-scheme: dark)` overriding `:root` vars — no JS toggle.
- Font CSS variables from `next/font` wired into `--font-sans` / `--font-mono`.
- Custom `@keyframes shimmer` + arbitrary-value utility for the skeleton sweep.
- **Skeleton pattern** — `FeedCardSkeleton` / `FeedGridSkeleton` mirror the real layout.
- Responsive grid: `sm:grid-cols-2 lg:grid-cols-3`; the flow diagram flips row→column on mobile.
- **Accessibility** — `aria-busy`, `aria-hidden`, `role="alert"`, `role="status"` +
  `aria-live="polite"`, `aria-describedby`, `htmlFor`/`id` label binding.

## 12. Code-organization patterns worth pointing at

- **One shared function, six call sites** — the whole thesis of the repo.
- **Data/presentation split** — `lib/*` has no JSX (except the OG renderer); components have no fetch.
- **Component pairs** — `FeedGrid` + `FeedGridSkeleton`, `FeedCard` + `FeedCardSkeleton`.
- **Config tables over conditionals** — the `DEMOS` array in `app/page.tsx`, `ROUTES` in `lib/site.ts`.
- **`readonly` / `as const`** — immutability throughout.
- **Named constants, no magic numbers** — `POST_LIMIT`, `SKELETON_COUNT`, `EXCERPT_MAX_LENGTH`,
  `QUERY_RETRY_COUNT`, `WRITE_LATENCY_MS`, `NOTE_MAX_LENGTH`.
- **Comments explain *why*** — e.g. why `connection()` is there, why `updateTag` not `revalidateTag`.

## 13. Trade-offs to be ready to defend

| Pattern | Wins | Costs |
|---|---|---|
| Server component | Zero client JS, no loading state | Nothing paints until upstream answers |
| Server action + Query | Caching, retries, refetch | Ships JS; actions are **queued**, reads serialize |
| Route handler | Visible, curl-able, reusable by other clients | Types don't cross the wire — response needs validating |
| Hybrid `use()` | Fetch starts pre-first-byte, page paints instantly | More moving parts; needs a Suspense boundary |
| `use cache` | Upstream paid once per window, not per visitor | Data stale for as long as `cacheLife` allows |
| Server action write | No endpoint, works pre-hydration | Must validate everything server-side |
